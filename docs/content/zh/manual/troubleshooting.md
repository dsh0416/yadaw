# 故障排除

从状态栏和 Heron 显示的警告开始。它们报告的是设备的实际运行状态，而不
只是请求的设置。

## 没有声音

1. 确认状态栏显示**音频运行中**。
2. 打开**设置 → 音频 → 设备**，选择目标输出。
3. 检查通道的输出路由与硬件输出映射。
4. 确认通道、总线与主输出没有被静音。
5. 检查是否有其他通道被独奏。
6. 观察从信号源到主输出方向的电平表活动。
7. 逐个旁路插件，找出阻断音频的插入。

如果电平表在动但扬声器没有声音，问题很可能出在主输出通道之后：硬件
映射、操作系统路由、音频接口控件或线缆。

## 输入不见了

1. 确认操作系统能识别该设备。
2. 为 Heron 授予麦克风或音频输入权限。
3. 在**音频 → 设备**下选择该设备并应用更改。
4. 重新打开音频通道的输入选择器。
5. 在 Windows 上，视情况安装并选择设备厂商的 64 位 ASIO® 驱动。

## 完全无法打开任何音频设备

当没有任何后端报告可用设备，或其他应用占用了音频接口时，在
**设置 → 音频 → 设备**下选择**模拟**后端。它会在不触碰硬件的情况下启动
引擎，让你可以继续编辑、编排与配置工程，并让 Heron 正常报告其余状态。
选中期间播放会被丢弃，因此要听到会话声音请切换回硬件后端。

## 输入监听不可用

在录音设置中启用软件监听，在音频轨上选择硬件输入，并确认音频引擎处于
运行状态。

## 音频出现爆音或报告 XRUN

- 增大 I/O 缓冲区；
- 关闭占用 CPU 较高的应用；
- 旁路开销较大的插件；
- 避免在会话期间运行音频性能基准测试；
- 查看性能监视器中的 CPU 与截止时间压力；
- 尽可能让输入与输出使用同一个带时钟的音频接口。

独立的输入与输出设备可能需要漂移校正。Heron 支持这一点，但单一接口
通常更容易调校。

## 监听延迟过高

逐步减小缓冲区，同时观察是否出现 XRUN。禁用监听路径上不必要的插件，
并用往返延迟读数比较不同配置。如果音频接口提供直接硬件监听，可以绕过
软件往返。

## VST® 3 插件缺失或被隔离

1. 确认安装了正确架构与 VST 3 版本的插件。
2. 打开声音浏览器并选择**重新扫描 VST3**。
3. 安装或更新插件后重启 Heron。
4. 查看启动消息中关于失败模块的信息。
5. 移除或旁路反复导致音频宿主停止的插件。

当存储的插件无法加载时，Heron 会保留一条合法路由，工程的其余部分仍可
正常使用。

## 工程未能正常关闭

下次打开时，当 Heron 报告工作状态比已保存的归档更新，选择**恢复工作
副本**。只有在你确实想丢弃较新的工作状态时，才选择**打开上次保存**。

对于被中断的录音，在移动或删除交换目录之前，先让 Heron 恢复并完成交换
目录中可用的音频。

## 寻求帮助

提交报告前，先搜索现有的 [GitHub issues](https://github.com/dsh0416/heron/issues)。
请附上：

- 操作系统与 Heron 版本；
- 音频接口、驱动、采样率与缓冲区；
- 确切的警告或错误信息；
- 重现问题的步骤；
- 旁路插件后问题是否仍然存在。

不要附带私人工程或录音，除非你已移除敏感内容并明确打算分享。
